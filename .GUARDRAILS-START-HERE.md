## 🚦 Three Layers Explained

### Layer 1: Rules (`.clauderules`)

**What:** Definitive constraints that Claude must never break.

**Examples:**
- Server code (src/server/**) must NEVER import from `vscode`
- Every MCP tool MUST have a `projectPath` argument
- All user-facing text MUST be in English + Chinese

**When:** Claude reads this FIRST before any task.

### Layer 2: Skills (`.claude/skills/`)

**What:** Step-by-step workflows for common development tasks.

**Available skills:**
- `add-mcp-tool.md` — Add new LSP capability
- `add-protocol-message.md` — Add inter-process communication
- `add-vscode-command.md` — Add button/menu/command
- `write-tool-tests.md` — Write test data + expected outputs

**When:** Claude uses this to implement a specific feature (follows steps 1-7).

### Layer 3: Validation (`.claude/hooks/`)

**What:** Automated checks that verify all rules are followed.

**When:** Run `./.claude/hooks/run-all-checks.sh` before every commit.

## ✅ Pre-Commit Checklist

Before pushing code:

```bash
# 1. Run automated validation
./.claude/hooks/run-all-checks.sh

# 2. All checks should pass ✅
# 3. Then test:
pnpm run check-types
pnpm run lint
pnpm test

# 4. Ready to commit
git push
```

## 🎓 Key Principles

| Principle | Why | Example |
|-----------|-----|---------|
| **Two-process architecture** | VSCode extensions can't register cross-window services | Server stays in Node.js; extension uses WebSocket |
| **Smart routing** | No tool should affect wrong projects | Every tool carries `projectPath` argument |
| **Protocol symmetry** | Communication must work both ways | Every message type needs handlers in BOTH files |
| **Bilingual always** | Project supports English + Chinese | All text in l10n files (both languages) |
| **Tests required** | Catch bugs early | New tools/messages need test data + expected files |
